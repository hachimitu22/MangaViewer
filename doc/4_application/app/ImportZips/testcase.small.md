# ImportZips テスト観点（small）

## このドキュメントの位置づけ（`readme.md` / `testcase.medium.md` との責務分担）
- `readme.md`: ImportZips の仕様・制約・運用時の振る舞いを定義する。
- `testcase.small.md`（本書）: 分岐・並び替え・判定ロジックなど、**副作用を切り離せる規則**を最小単位で検証する。
- `testcase.medium.md`: 実依存（zip読取/保存/DB/ログ）を繋いだ統合動作を検証する。

---

## small 観点（t-wada を意識した粒度）

### 1) zip対象判定（拡張子の大文字小文字非依存）
**前提**
- ファイル名候補として `a.zip`, `b.ZIP`, `c.ZiP`, `d.zipx`, `e` を用意する。

**操作**
- 「zip対象判定」ロジックを実行する。

**期待結果**
- `*.zip`（大文字小文字差異含む）のみ true となる。
- `zipx` や拡張子なしは false となる。

### 2) 直下エントリ選別（zip以外はスキップ対象）
**前提**
- `<dir>` 直下の列挙結果として、zipファイル・非zipファイル・ディレクトリを混在させる。

**操作**
- 「処理対象zip抽出」ロジックを実行する。

**期待結果**
- 処理対象にはzipのみ残る。
- 非zip/ディレクトリはスキップ対象として理由付きで返せる。

### 3) 画像拡張子判定（拡張子ベース）
**前提**
- `jpg/jpeg/png/webp/gif/bmp/avif` と、非対応拡張子を含むファイル名候補を用意する。

**操作**
- 「画像拡張子判定」ロジックを実行する。

**期待結果**
- 許可拡張子のみ true となる。
- 非対応拡張子は false となる。

### 4) zip内エントリ抽出（直下のみ対象）
**前提**
- zipエントリ一覧として `001.jpg`, `sub/002.jpg`, `003.png`, `note.txt` を用意する。

**操作**
- 「登録対象画像抽出」ロジックを実行する。

**期待結果**
- `001.jpg`, `003.png` のみ対象になる。
- `sub/002.jpg` は配下ディレクトリとして除外される。
- `note.txt` は非画像として除外される。

### 5) 拡張子なしファイルの扱い
**前提**
- zipエントリに `cover`（拡張子なし）を含める。

**操作**
- 「登録対象画像抽出」ロジックを実行する。

**期待結果**
- `cover` は画像実体であっても対象外になる。
- 無視理由を構築できる。

### 6) 画像ゼロ件判定
**前提**
- 抽出結果の画像一覧を 0 件にする。

**操作**
- 「zip登録可否判定」ロジックを実行する。

**期待結果**
- 失敗判定となり、理由は「画像なし」になる。

### 7) 画像順序（basename自然順・大文字小文字区別）
**前提**
- `1.jpg`, `2.jpg`, `10.jpg`, `A.jpg`, `a.jpg` を入力する。

**操作**
- 「登録順ソート」ロジックを実行する。

**期待結果**
- 数値を含む basename が自然順で並ぶ。
- `A.jpg` と `a.jpg` は同一視せず、比較規則どおりに並ぶ。

### 8) メディアタイトル生成
**前提**
- zipファイル名 `my.book.v1.zip` と `SAMPLE.ZIP` を用意する。

**操作**
- 「タイトル生成」ロジックを実行する。

**期待結果**
- 拡張子を除去した `my.book.v1`, `SAMPLE` が返る。

### 9) 終了コード決定ロジック
**前提**
- 集計パターン（全件成功 / 一部成功 / 全件失敗）と、事前チェック失敗を用意する。

**操作**
- 「終了コード決定」ロジックを実行する。

**期待結果**
- 全件成功 = 0
- 一部成功 = 1
- 全件失敗 = 2
- 事前チェック失敗 = 3

### 10) 例外時の継続可否判定（zip単位）
**前提**
- 2件のzip入力で、1件目のみ例外発生、2件目は正常処理可能な状態を作る。

**操作**
- zipループの制御ロジックを実行する（I/Oはモック化）。

**期待結果**
- 1件目は failure として記録される。
- 2件目の処理は継続される。
- 全体が途中中断しない。

### 11) ログレベル選択ルール
**前提**
- 代表イベント（通常進行、zip不備、読取失敗/保存失敗）を用意する。

**操作**
- 「ログレベル決定」ロジックを実行する。

**期待結果**
- 通常進行/成功/サマリは `info`。
- zip不備は `warn`。
- 読取失敗/保存失敗/予期せぬ例外は `error`。

## テスト実装方針（small）
- small では zip 展開やDB保存を直接扱わず、判定・変換・分岐ルールを関数単位で固定する。
- I/O 依存はモック/スタブで置換し、失敗理由と分岐結果（継続/中断、終了コード）を明示的に検証する。
- ログ検証は文面完全一致を避け、`level` / `zip名` / `理由コード` などの意味的フィールドを優先する。
