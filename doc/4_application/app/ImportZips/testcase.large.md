## ケース詳細

### L-IMPORT-01: ディレクトリ直下のzipを一括取り込みできる
- **前提**
  - 正常zipを複数（例: `book-1.zip`, `book-2.zip`）配置する。
  - 各zipは有効画像（`.jpg/.jpeg/.png/.gif/.webp`）を1枚以上含む。
- **操作**
  - `npm run import -- <fixtureDir>` を実行する。
- **期待結果**
  - すべて success で処理される。
  - メディアがzip件数分登録される。
  - 終了コード `0` を返す。

### L-IMPORT-02: zip以外の直下エントリはスキップされる
- **前提**
  - `fixtureDir` 直下に zip と `README.txt`、サブディレクトリを混在させる。
- **操作**
  - `npm run import -- <fixtureDir>` を実行する。
- **期待結果**
  - zipのみ処理対象となる。
  - 非zipエントリごとにスキップログが出力される。

### L-IMPORT-03: 一部失敗時は終了コード1で成功分のみ永続化される
- **前提**
  - 成功zipと、破損画像により失敗するzipを混在させる。
- **操作**
  - `npm run import -- <fixtureDir>` を実行する。
- **期待結果**
  - 終了コード `1` を返す。
  - 成功zip分のみメディアが登録される。
  - サマリが総件数/成功件数/失敗件数を正しく示す。

### L-IMPORT-04: 全件失敗時は終了コード2で永続化されない
- **前提**
  - 対象zipをすべて失敗条件（暗号化zip、画像なしzip等）にする。
- **操作**
  - `npm run import -- <fixtureDir>` を実行する。
- **期待結果**
  - 終了コード `2` を返す。
  - 新規メディアが1件も登録されない。

### L-IMPORT-05: 対象がディレクトリでない場合は終了コード4で即時終了する
- **前提**
  - `<dir>` に既存ファイルパスを指定する。
- **操作**
  - `npm run import -- <filePath>` を実行する。
- **期待結果**
  - zip処理ループに入らない。
  - 終了コード `4` を返す。

## large テスト方針
- `npm run start:test` で起動した環境に対し、CLIプロセスを別途実行して検証する。
- 検証は「終了コード」「ログサマリ」「永続化結果（API/DB）」の3観点を必須とする。
- fixtureは `__tests__/fixtures/importZips/` を利用し、再現性を優先する。
