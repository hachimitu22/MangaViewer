# ImportZipsPolicy テストケース（large）

## 目的
- 実サーバー相当の起動構成（`npm run start:test`）と実ストレージ/DBを利用した
  長経路テストで、`ImportZipsPolicy` が `ImportZips` 実行結果へ与える影響を検証する。
- medium では見えにくい「プロセス境界・実ファイル配置・サマリ整合」の退行を検知する。

## テスト観点

### L-POLICY-01: 実行プロセス境界を跨いでも許可拡張子契約が維持される
- **前提**
  - E2E用fixtureとして `.jpg/.jpeg/.png/.gif/.webp` と `.bmp` を含むzipを用意する。
- **操作**
  1. `npm run start:test` でアプリを起動する。
  2. 別プロセスで `npm run import -- <fixtureDir>` を実行する。
  3. APIまたはDBクエリで登録content件数を確認する。
- **期待結果**
  - 許可拡張子のみ登録対象となる。
  - `.bmp` は登録されない。

### L-POLICY-02: 混在結果時の終了コードと永続化結果が一致する
- **前提**
  - 成功するzipと失敗するzip（暗号化/破損等）を混在させる。
- **操作**
  - `npm run import -- <fixtureDir>` を実行し、終了コード・ログ・永続化結果を突合する。
- **期待結果**
  - 終了コードが `1`（一部成功）となる。
  - DB上の登録件数は成功zip数と一致し、失敗zip分の不整合レコードが残らない。

### L-POLICY-03: 0件入力での終了コード0と副作用なしを確認する
- **前提**
  - 対象ディレクトリ直下にzipが存在しない。
- **操作**
  - `npm run import -- <emptyDir>` を実行する。
- **期待結果**
  - 終了コード `0` を返す。
  - 登録件数が増加しない。
  - サマリに総件数0/成功0/失敗0が出力される。

---

## large テスト方針
- large は「実行経路の妥当性」を担保し、詳細ロジック期待値は small/medium へ寄せる。
- flaky 回避のため、fixture は固定データを使い、時刻依存・順序依存のアサーションを避ける。
- 失敗時に原因を追いやすいよう、終了コード・サマリログ・永続化状態を3点セットで観測する。
